# Проверка основного сценария по официальным критериям

Источник: [requirements.md, разделы 3–5](../ai-review/requirements.md).
Дата проверки: 23 сентября 2026 года. Оценка баллов жюри не прогнозируется:
наличие адаптера и успешный mock-тест не доказывают качество настоящей модели.

## На что направлена работа

| Официальный критерий | Баллы | Что показывать из существующей реализации | Что ещё нужно подтвердить |
| --- | ---: | --- | --- |
| Соответствие задаче и работоспособность | 25 | Загрузка → STT → диаризация → alignment → единый анализ → протокол | Полный прогон настоящих моделей, в особенности KZ/RU-KZ |
| Техническая реализация | 25 | Локальные адаптеры, JSON Schema, цитаты, сохранение результата, обработка ошибок, тесты | Реальное качество диаризации/LLM, а не только контракты |
| README и воспроизводимость | 25 | Команды установки, подготовка весов отдельно, ENV, UI/API, ограничения | Повторить запуск с выбранными весами на компьютере демонстрации |
| Ценность и применимость | 15 | Из реплик получаются поручения с ответственными/сроками, доказательствами и готовым файлом | Показать конкретные корректные поручения на реальной демонстрационной записи |
| Потенциал развития и оригинальность | 10 | Независимый LocalLLMClient, один совместный анализ, ссылки на исходные реплики, локальный контур | Объяснить пользу этих решений; новые интеграции для этого не нужны |

Приоритет — обязательный минимум и подтверждение основного сценария. Teams/Zoom,
дашборды, напоминания, СЭД и биометрическая идентификация в эту работу не добавлялись.

## Проверка компонентов

| Компонент | Проверено в реализации | Ограничение/результат |

| STT | Локальный faster-whisper, transcribe, язык auto/multilingual, timestamps, CPU/CUDA настройки | Реально проверялась small/CPU; качество KZ/RU-KZ недостаточно подтверждено |
| Diarization | Локальные Community-1 assets, offline, отключённая телеметрия, SPEAKER-метки, ручные имена | На момент проверки config.yaml Community-1 отсутствует; реальный inference не подтверждён |
| Alignment | Сохранение текста/ID/времени, пересечения интервалов, неоднозначность нескольких голосов | Реплики не делятся по словам; имя не угадывается |

| Summary | Один ответ с поручениями, ссылки/цитаты, проверка числовых литералов, точное копирование выбранных задач | Реальная полнота и смысловая правильность ещё не измерены |

| Tests | Unit/HTTP, оба исходных протокола, browser flow, кеш и отсутствие лишних вызовов | ML в автоматическом сквозном сценарии — явно обозначенные doubles |

адаптеры, alignment, extraction/summary, экспорт, схемы, тесты и инструкции запуска.
Рабочая архитектура сохранена.

## Исправлено при проверке

1. **Потеря условия в кратком саммари документа.** Раньше раздел «Основные поручения»
   выводил только description: условное «расторгнуть договор» могло выглядеть как
   безусловное решение, хотя таблица ниже содержала условие. Теперь краткий список
   сохраняет condition, исполнителя, срок, milestones и источники в обоих форматах.
2. **Недостаточная привязка полей к показанной цитате.** Раньше исполнитель/срок/
   условие могли подтверждаться любой частью длинного сегмента, даже если evidence
   цитировала другой фрагмент. Теперь эти поля подтверждаются самими цитатами;
   для исполнителя также допустимо подтверждённое имя speaker. Срок milestone
   проверяется по цитатам именно его source IDs. Prompt уточнён под этот контракт.

Добавлены регрессионные проверки обеих ошибок и сохранения назначения от первого
лица по подтверждённому speaker. Дополнительные LLM-вызовы не добавлены.
Это лексическая проверка: правильность выбора исполнителя и трактовки срока
всё равно необходимо проверять на настоящей модели.

Изменены: `app/services/extraction.py`, `app/services/export.py`,
`app/prompts/meeting_analyzer.txt`, `tests/unit/test_extraction.py`.
Добавлен `tests/unit/test_export.py`; актуализирована цитата в fixture
`tests/unit/test_summarization.py`, где раньше новые сроки добавлялись только
в исходный текст. Обновлена документация.

Осталось прежнее предупреждение Starlette TestClient.

## Самый важный следующий шаг

На этой машине подготовлена Whisper small. Команда Ollama не найдена в PATH,
и запрос только метаданных к `127.0.0.1:11434/api/tags` не установил соединение.
Файл `models/speaker-diarization-community-1/config.yaml` отсутствует.
Новые функции не устранят эти препятствия к демонстрации.

Порядок подготовки:

1. Подготовить Community-1 с разрешённым доступом через существующий
   `scripts/prepare_diarization.py`; токен вводится только локально.
2. Подготовить локальную Ollama-модель, включить `OLLAMA_NO_CLOUD=1` в процессе
   сервера и задать её имя в `HACKALEM_OLLAMA_MODEL` для backend.
3. Запустить `scripts/evaluate_protocols.py --run-local`. Вручную проверить оба
   текстовых протокола по девяти правилам, а не объявлять генерацию успешной оценкой.
4. Прогнать разрешённую запись с несколькими говорящими: русский, казахский и
   естественное смешение языков. Проверить STT, голоса, поручения и файлы вместе.
5. Зафиксировать модель, устройство, настройки, время и конкретные ошибки. Только
   после этого выбрать конфигурацию демонстрации. CUDA/large-v3 пока не проверены;
   переключение ENV само по себе не доказывает работоспособность на другом устройстве.

Команды уже есть в [README](../README.md) и
[тестировании и метриках](TESTING_AND_METRICS.md). Автоматический переход к облаку
или подстановка fixtures при отсутствии весов не выполняется.

## Короткая демонстрация практической ценности

Сначала проведите полный локальный прогон на той же конфигурации, которая будет
использоваться на показе. Сохраните URL встречи и полученные DOCX/PDF.

| Шаг показа | Что видит жюри | Какую пользу подтверждает |
| --- | --- | --- |
| Загрузить разрешённую запись и запустить обработку | Один пользовательский сценарий и реальные стадии | Секретарю не нужно запускать отдельные инструменты вручную |
| Открыть поручения | Суть, исполнитель, срок или явно неизвестное значение | Понятно, кто и что должен сделать |
| Нажать «Фрагмент» и открыть цитату | Исходная реплика и время | Результат можно проверить, а не принимать на веру |
| Показать Ерлана/подразделение и пересмотр срока, если они есть в выбранной записи | Исполнитель отличается от говорящего; итоговый срок сохранён | Покрыты сложные случаи из официальных материалов |
| Показать условное решение и отсутствие срока | Условия не теряются, дата не выдумывается | Снижается риск неверного управленческого поручения |
| Скачать протокол | Документ с таблицей, summary и транскриптом | Результат пригоден для дальнейшей проверки и использования |
| Переключить вкладку/повторно открыть результат | Сохранённый результат; метрики показывают 0 новых LLM calls | Экономный повторный доступ без нового анализа |

Не заявляйте процент экономии времени, точность или ускорение без измерений.
Если показан заранее сохранённый результат, обозначьте это прямо. При недоступных
моделях можно показать технический тест, но нельзя выдавать его за реальный AI-прогон.

## Граница готовности

Код обязательных стадий присутствует, контракты и взаимодействие проверены.
Заявлять полный максимум по работоспособности преждевременно: реальные веса
диаризации/LLM и качество естественного RU/KZ сценария ещё требуют проверки.
Главный приоритет следующей итерации — устранить именно этот разрыв.
