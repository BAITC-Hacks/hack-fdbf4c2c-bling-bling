## Замечания и решения этого этапа

- Статус `created` не должен изображать готовый протокол. Добавлены отдельные
  `uploading` и `audio_ready`; последний означает только подготовленное аудио.
- Существующие записи нельзя потерять при добавлении файлов. Используется новая
  таблица `meeting_audio`, без удаления/пересоздания старой таблицы `meetings`.
- Клиентское имя не должно становиться путем. Оба локальных пути генерируются
  из UUID; формат проверяется расширением и реальным декодированием.
- Для поврежденных данных, пустой записи, отсутствия ffmpeg, таймаута и лимитов
  предусмотрены явные ошибки и удаление частичных результатов.
- Конкурирующие и повторные загрузки отклоняются атомарной сменой статуса в SQLite.
- ffmpeg не найден в системном PATH; для реальных тестов установлен локальный
  бинарник через тестовую зависимость imageio-ffmpeg. Путь запуска документирован.
- ENV-файл не добавлялся. Конфигурация работает с defaults/переменными окружения.
- Остались ограничения: синхронное преобразование, временная multipart-буферизация,
  отсутствие восстановления после аварии, авторизации и промышленного sandbox
  для декодирования недоверенных медиа. Они обозначены в README и не скрываются.
- Версии зависимостей заданы диапазонами, полного lock-файла пока нет.

## Проверки предыдущего этапа загрузки

Тесты генерируют синтетические записи: все пять форматов, включая видео MP4/WebM
с аудио. Проверяются реальный ffmpeg, mono/16000 Hz/16-bit PCM, исходный файл,
статусы, база после перезапуска, ошибки, очистка, повторная загрузка и лимиты.
Таймаут проверяется через подмену subprocess; успешная конвертация не подменяется.
Предыдущие тесты API и ENV запускаются вместе с новыми. Это не тесты точности ML.

Итог запуска: **30 passed**; реальный HTTP `/health` — **200**. Единственное
предупреждение — deprecation стороннего TestClient для httpx; ошибок нет.
