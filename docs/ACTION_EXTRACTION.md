# Этап 7: извлечение поручений

Источник требований: [ai-review/requirements.md](../ai-review/requirements.md),
F-05, F-09, §4 и примеры §9; дополнение — правила этапа 7 пользователя.

## Реализация

Обновление этапа 8: инструкция вынесена в `app/prompts/action_items.txt`, загружается
как UTF-8 независимо от текущей папки. Новые результаты имеют `prompt_version="2"`;
чтение старых результатов версии 1 сохранено. Правила этапа 7 сохранены.

`ActionItemExtractionService` принимает список `ExtractionSegment` с исходными
ID, текстом и необязательным подтвержденным именем говорящего. Он зависит от
интерфейса `LocalLLMClient.generate_json`, а не от Ollama. Адаптер `OllamaClient`
подключается при создании приложения; другую локальную LLM можно подключить,
реализовав тот же интерфейс. Mock в production не используется.

Путь API: сохраненный STT → весь список сегментов → локальная LLM с JSON Schema →
Pydantic → проверка цитат/ссылок → объединение точных дублей → SQLite.
Ни STT, ни диаризация повторно не запускаются. Stage 6/alignment пока отсутствует,
поэтому API не приписывает репликам имена из отдельной диаризации. Без достаточного
контекста исполнитель остается `null`; говорящий не назначается автоматически.

## Подготовка и запуск

Установите Ollama и заранее скачайте совместимую локальную instruction-модель,
поддерживающую RU/KZ и structured output. Название модели не зафиксировано в коде.
Модель нужно проверять на примерах ниже: поддержка JSON не доказывает качество.

В PowerShell, в процессе запуска **самого сервера Ollama**:

```powershell
$env:OLLAMA_NO_CLOUD = '1'
$env:OLLAMA_HOST = '127.0.0.1:11434'
ollama serve
```

Если Ollama уже запущена приложением Windows, завершите ее и перезапустите с этой
настройкой. Переменная только в процессе FastAPI не меняет работающий сервер Ollama.
Официальное описание локального режима: [Ollama FAQ](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features).

В другом окне, после подготовки локальной модели:

```powershell
ollama list
# Укажите точное имя локальной модели из списка, без cloud-тега.
$env:HACKALEM_OLLAMA_MODEL = 'имя-установленной-локальной-модели'
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

ENV-файл не нужен. По умолчанию имя модели пустое: это дает понятную 503 при
извлечении, не запускает произвольную модель и не мешает `/health`, загрузке и STT.
Во время обработки нет `pull`, автоустановки, облачного fallback или API-ключей.

| ENV | Default | Смысл |
| --- | --- | --- |
| `HACKALEM_OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Только HTTP loopback |
| `HACKALEM_OLLAMA_MODEL` | пусто | Установленная локальная модель |
| `HACKALEM_LLM_TIMEOUT_SECONDS` | 180 | Таймаут HTTP; connect — 5 секунд |
| `HACKALEM_LLM_NUM_CTX` | 32768 | Запрошенное окно контекста, ограничивается возможностями модели |
| `HACKALEM_LLM_NUM_PREDICT` | 4096 | Лимит генерируемых токенов; меньше контекста |
| `HACKALEM_EXTRACTION_MAX_CHARS` | 60000 | Дополнительный лимит входного текста |
| `HACKALEM_EXTRACTION_ATTEMPTS` | 2 | Всего попыток при невалидном JSON/ссылках, максимум 3 |

Контекст оценивается консервативно по UTF-8 байтам prompt/schema/template плюс
резерв на ответ. Поэтому фактически допустимый текст может быть существенно
короче 60000 символов. `truncate=false` и `shift=false` отправляются серверу;
нужна версия Ollama с поддержкой этих полей. Переполнение дает 413, исходные
реплики не обрезаются. Автоматическая обработка длинных встреч по частям с общей
сверкой поручений пока не реализована. Увеличение контекста требует больше RAM.

## API и хранение

После успешного STT:

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/meetings/$($meeting.id)/extract-action-items" -Method Post
Invoke-RestMethod "http://127.0.0.1:8000/meetings/$($meeting.id)/action-items"
Invoke-RestMethod "http://127.0.0.1:8000/meetings/$($meeting.id)/action-items/status"
```

POST синхронный, без тела. GET возвращает сохраненный результат без вызова LLM.
Статус этапа: `not_started → running → ready`, независимо от `Meeting.status`.
Повтор во время работы или после завершения дает 409. Для эксперимента с другой
моделью создайте новую встречу. При ошибке claim удаляется и запрос можно повторить.
После аварийного завершения процесса `running` автоматически не восстанавливается.

Результат хранится в новой таблице SQLite `meeting_extractions`. Поручения и
снимок исходных сегментов сохраняются одной транзакцией. Ответ API содержит:

- `action_items` — проверенные объекты схемы ниже;
- `source_segments` — исходные ID/тексты и подтвержденный speaker либо `null`;
- `source_transcript_sha256` — SHA-256 канонического `TranscriptRaw.model_dump_json()`;
- `model` — настроенное имя модели, `prompt_version` — версия инструкции.

Это позволяет посмотреть цитаты и полные исходные реплики даже после изменения
файла транскрипта. Снимок хранится локально вместе с результатом, не в Git.
Отдельный `action_items.json` не создается; JSON можно получить через GET.

Пример структуры **внутреннего ответа LLM**, не результат реального прогона:

```json
{
  "action_items": [
    {
      "description": "Подготовить претензию",
      "responsible": "Ерлан",
      "deadline_raw": "до пятницы",
      "source_segment_ids": [15],
      "confidence": 0.92,
      "decision_type": "assigned",
      "condition": null,
      "milestones": [],
      "evidence": [
        {"segment_id": 15, "quote": "Ерлан, до пятницы подготовьте претензию."}
      ]
    }
  ]
}
```

Все поля обязательны. `responsible`, `deadline_raw`, `condition` допускают `null`.
У milestone есть `description`, `deadline_raw`, `source_segment_ids`. Для условного
решения обязательны `decision_type="conditional"` и непустое исходное `condition`.
Предложения без принятия исключаются; пустой результат — `{"action_items": []}`.
`confidence` — самооценка LLM, а не измеренная или откалиброванная вероятность.

## Правила и проверка доказательств

| Правило пользователя | Реализация и граница проверки |
| --- | --- |
| 1–3. Исполнитель отличается от говорящего, может отсутствовать или быть подразделением | Prompt требует конкретного исполнителя, не назначает speaker автоматически; имя должно присутствовать в подтверждающих репликах/метаданных, иначе null |
| 4–5. Не выдумывать сроки, сохранять относительные | nullable deadline_raw; непустое значение должно встречаться в цитируемых сегментах; нормализованных дат и текущего года нет |
| 6. Пересмотр срока | Модель видит всю запись и должна учитывать финальное решение вместе с возражением; смысловая корректность проверяется отдельным acceptance case |
| 7. Повторы в итогах | Prompt требует объединить перефразированные повторы; точные дубли объединяются кодом с сохранением ссылок/цитат; конфликт сроков требует повторного ответа модели |
| 8. Предложение и принятое поручение | Непринятые предложения исключаются инструкцией; схема не допускает proposal как поручение |
| 9. Условность | Отдельные decision_type/condition; схема запрещает условное решение без условия и безусловное с условием |
| 10. Число в содержании не является сроком | Явное правило и case с пятью рабочими днями; принадлежность срока задаче оценивает LLM |
| 11. Несколько сроков | milestones сохраняют каждый результат, его срок и собственные ссылки |
| 12. Обоснование | Все ID должны существовать; evidence покрывает каждый ID, quote совпадает с исходным текстом; ссылки milestones входят в ссылки поручения |

Проверка цитат допускает нормализацию регистра/пробелов/Unicode, не заменяет смысл
или даты. Точные дубли объединяются только при согласованных сроках и milestones;
confidence берется минимальный. JSON с лишними полями, строкой вместо числа,
NaN, Markdown-оберткой или повторяющимися ключами отклоняется. Невалидный результат
не сохраняется. После ограниченного повтора возвращается 502.

Наличие реальной цитаты не доказывает правильность интерпретации: исполнитель,
принятие предложения, пересмотр срока и смысловое объединение требуют проверки
на настоящей модели. Система не гарантирует отсутствие смысловых ошибок.

## Локальность

HTTP-клиент отключает proxy из ENV и redirects, `localhost` преобразуется в числовой
loopback. Перед каждым chat делается `/api/show` без текста встречи: нужны непустые
локальные `model_info`, отсутствие `remote_host`/`remote_model`; cloud-имена запрещены.
Сервер должен работать с `OLLAMA_NO_CLOUD=1`. Приложение не управляет чужим процессом
Ollama; для проверки закрытого контура дополнительно блокируйте внешний исходящий
трафик процесса Ollama. Пользовательский транскрипт передается как данные; у LLM
нет инструментов исполнения задач или отправки сообщений.

Schema передается в `format`, затем ответ проверяется Pydantic.
[Structured outputs](https://docs.ollama.com/capabilities/structured-outputs).
Поля локальности и контроля контекста сверены с
[контрактами API Ollama](https://github.com/ollama/ollama/blob/main/api/types.go).
Ответы с `done=false`, `done_reason=length` и tool calls не считаются результатом.

## Ошибки и проверки

503: модель не задана/не установлена, Ollama недоступна, локальность не подтверждена.
504: таймаут. 413: превышен лимит текста/контекста. 502: невалидный или незавершенный
ответ. 409: нет готового транскрипта, запрос уже выполняется/завершен. Детали ошибок
не содержат пользовательский текст, ответы LLM или внутренние сообщения сервера.

Контрактные тесты выполняются вместе с прежними:

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe scripts/smoke.py
```

Тесты явно используют doubles LLM, в том числе настоящий HTTP по loopback с
тестовым сервером. Они подтверждают схему, проверки, транспорт и сохранение;
не подтверждают понимание содержания настоящей моделью.

После установки и настройки локальной модели:

```powershell
.venv/Scripts/python.exe scripts/evaluate_extraction.py
```

10 cases в `tests/fixtures/extraction_cases.json` охватывают правила 1–12,
RU/KZ, условные решения и инструкции внутри транскрипта. Скрипт вызывает только
настоящий `OllamaClient`, сохраняет ответы/источники в
`data/extraction-evaluation/report.json`. Он сверяет число поручений, исполнителей,
сроки, условия, источники и milestones. Описания и полноту затем проверяет человек:
автоматический rubric не является универсальной оценкой семантики.

В текущей среде Ollama недоступна, модель не задана. Запуск оценки завершился
`llm_not_configured`, остальные 9 cases не выполнялись. Качество извлечения пока
не подтверждено. Для оценки на полном совещании также нужны приемлемое качество
STT и достаточный контекст модели. Сервис summary добавлен на этапе 9
([описание](MEETING_SUMMARY.md)); экспорт остается будущим этапом.
