# Извлечение поручений, сроков и саммари

## Алгоритм

1. Передавать локальной языковой модели сегменты с идентификаторами, именами подтверждённых участников, датой и часовым поясом совещания.
2. Сначала находить кандидатов поручений и доказательства, затем разрешать исполнителей и сроки с учётом соседних реплик. Различать предложение, принятое решение, поручение и простой доклад о показателях.
3. Для длинного текста извлекать кандидатов по частям с контекстом, затем выполнять общий проход по уточнениям и повторам. Финальное подытоживание не должно создавать дубли ранее выданных поручений.
4. Требовать структурированный ответ по контракту `ActionItem`. Инструкция модели: не выдумывать исполнителя или срок, возвращать `null`, сохранять исходную формулировку срока и ссылки на подтверждающие реплики.
5. Отдельно проверять схему ответа, идентификаторы источников, даты и противоречия. Валидный JSON сам по себе не доказывает правильность извлечения.
6. Объединять повторы одного действия с тем же исполнителем. Не объединять разные действия только из-за совпадения имени. При разделении составного поручения сохранять общую связь и разные сроки подзадач.
7. Показывать спорные поля секретарю. После изменения транскрипта помечать зависимые поручения и саммари устаревшими; пересчёт не должен молча стирать ручные правки.

## Сроки

Всегда хранить `due_raw` вместе с нормализованным значением. Срок отсчитывается от даты совещания, а не даты загрузки файла или системных часов разработчика.

- «15 октября» без известного года: сохранять исходную формулировку, требовать подтверждения года. Даже при известной дате совещания отмечать сделанное предположение.
- «До пятницы», «к среде», «на этой неделе»: применять согласованные правила календаря и часового пояса. Неоднозначность, например упоминание пятницы в пятницу, передавать на проверку.
- «На следующей неделе»: хранить интервал недели, не подменять точным днём без подтверждения.
- «За две недели»: вычислять только при известной точке отсчёта и согласованной трактовке календарных дней.
- «После совещания с подрядчиками»: хранить зависимость от события, а не придуманную дату.
- Отсутствующий срок: `due_kind=missing`, `due_date=null`. Не напоминать о просрочке по вымышленному сроку.

## Регрессионные примеры из docs

| Пример | Ожидаемое поведение |
| --- | --- |
| №1: пять явных поручений по химической промышленности | Сохранить пять действий; юридический департамент — допустимый исполнитель без персонального имени |
| №1: «две недели» → «три недели» → «к пятнадцатому октября» | Одно поручение об аудите с окончательным сроком и источниками уточнения |
| №1: финальное перечисление по безопасности | Не дублировать пять уже выданных поручений; базовый эталон содержит десять поручений по двум темам |
| №1: «к среде будет ответ» | Учесть обещание Айнур как уточнение срока заключения юристов |
| №2: претензия поставщику | Исполнитель Ерлан, а не говорящая Ботагоз; Ерлан может отсутствовать среди голосов |
| №2: справка после совещания | Событийный срок, отдельное действие Жандоса |
| №2: обучение и смета | Неделя относится к смете, месяц — к закрытию очереди; при разделении сохранять разные сроки |
| №2: уведомление и шаблон договора | Срок не указан; «пять рабочих дней» — условие будущего договора, не срок подготовки шаблона |

Во втором примере итоговая таблица группирует поручения в шесть строк. Не использовать число шесть как жёсткий критерий: допустимо разделить составные действия. Сравнивать полноту смысла, исполнителей и сроки, включая детали реплик, не попавшие в итоговую таблицу.

## Саммари

Формировать разделы «Темы», «Ключевые факты», «Решения», «Поручения», «Открытые вопросы». Сохранять привязку фактов к сегментам, отделять высказанный риск от установленного факта. Например, предположение о формальности инструктажей нельзя превращать в подтверждённое заключение проверки.

Показатели 71%, 8%, 60% из первого примера и 94%, 68%, 12% из второго проверять отдельно: не менять направление показателя и не переносить его между темами. Если источники противоречат друг другу, отразить расхождение вместо выбора удобного значения.
