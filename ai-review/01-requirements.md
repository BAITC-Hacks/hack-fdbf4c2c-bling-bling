# Требования и границы

## Матрица реализации

| ID | Требование из ТЗ | Что реализовать | Проверка |
| --- | --- | --- | --- |
| R1 | Распознавание речи | Локальная обработка аудио, транскрипт с временными метками | Сопоставить с вручную проверенным текстом |
| R2 | Русский язык | Распознавание и извлечение смысла русской речи | Русскоязычная запись и эталон поручений |
| R3 | Казахский язык | Сохранение казахского текста, имён и смысла | Отдельная запись и проверка носителем языка |
| R4 | Шала-казахский | Переключение языков внутри реплики без принудительного перевода | Смешанная запись, проверка имён и поручений |
| R5 | Поручения | Суть, исполнитель, срок и ссылки на реплики | Сопоставление с размеченными поручениями |
| R6 | Диаризация и привязка к человеку | Устойчивые идентификаторы говорящих и подтверждение имён | Проверить смены говорящих и исправление соответствий |
| R7 | Экспорт PDF/DOCX | Оба формата из одной версии проверенного протокола | Открыть файлы, проверить таблицы и кириллицу |
| R8 | Саммари | Итоги по темам, решения, риски и поручения | Каждый факт подтверждается транскриптом |
| R9 | Закрытый контур и приватность | Локальные модели, хранилище и генерация документов | Полный цикл при отключённом внешнем интернете |
| R10 | Уведомление о записи | Подтверждение уведомления участников перед записью; для загрузки — подтверждение права обработки | Проверить основной пользовательский сценарий |
| R11 | Напоминания из сценария 2 | Локальная очередь напоминаний о приближении срока и просрочке | Искусственные часы, повторный запуск без дублей |

R1–R7 соответствуют обязательному минимуму; R8–R11 следуют из остальных разделов ТЗ. Поддержка обоих форматов экспорта — выбранный объём проекта: запись PDF/DOCX в ТЗ не уточняет, достаточно ли одного.

## Входные каналы и этапы

Сначала реализовать загрузку аудио/видеофайла с извлечением аудиодорожки. Затем добавить live-поток и адаптеры участия в Teams, Zoom и Google Meet. ТЗ перечисляет эти входы, но не уточняет обязательность каждого для прототипа: демонстрация загрузки не подтверждает реализацию интеграций. Фиксировать их статус отдельно и согласовать объём сдачи.

Для адаптеров передавать запись на локальную обработку. Не использовать встроенную облачную транскрибацию. Совместимость подключения к внешним конференциям с конкретным закрытым контуром требует отдельного решения; базовый офлайн-сценарий должен работать самостоятельно.

## Дополнительные возможности

После основного цикла реализовывать дашборд статусов, рассылку выдержек, классификацию срочности/направления, интеграцию с СЭД и голосовую идентификацию. Полноценная СЭД и промышленное развёртывание вне обязательной части. Напоминания не считать реализованными только за счёт наличия дашборда.

Несмотря на упоминание on-premise среди дополнительных возможностей, раздел ограничений прямо требует возможность локального размещения и запрещает внешние API для аудио/текста. Поэтому локальность заложить с первого этапа, включая модель анализа текста.
